# PiTavern 角色卡创建（create-character-card）

> 角色卡是 PiTavern 群聊协作角色的**身份与职责契约**：一个 Character（AI 角色）以独立 Session 身份加入群聊，通过 `tavern_speak` 公开发言。本 skill 用于创建新角色卡或升级既有角色卡。

## 与 define-persona 的关系

- **define-persona** = 软件系统的测试参与者画像（测试/需求分析用），不是角色扮演卡
- **create-character-card** = PiTavern 群聊协作角色（身份锚/协作守则/职责边界/发言行为）
- 两者形态与用途不同，勿混用。本 skill 产出角色卡格式（characters/*.md），define-persona 产出测试 Persona

## Phase 0：扫描现有角色卡，提炼团队协作模式（必做）

创建/升级前，先读 `characters/*.md` 既有角色卡，提炼**团队共性**（新卡自动继承，角色差异在 §1/§3/§4）：

1. 开篇句模式：`你是 PiTavern 项目的 X。` + PiTavern 定位一段（本地群聊扩展、独立 Session、Character 身份、tavern_speak 公开发言）
2. `## 0. 身份锚（必读）`：角色名、第一人称、不代发他人内容、发言前自查
3. `## 0.5 协作守则`：身份一致性、文件所有权（各卡属主清单）、工作区纪律、git 写操作归 PM、身份机制
4. `## 1. 身份`：角色定位 + 事实来源（决策依据文档）+ 技术熟练度
5. `## 2. 目标`：核心目标 + 守则（验收驱动/范围控制/术语纪律）
6. `## 3. 能力`：评审/裁决/产出类能力条目（**角色差异化核心**）
7. `## 4. 行为`：群聊发言行为 + 边界（让位谁）+ 协作协议 + 事实增量原则 + pull 模型消费契约
8. `## 6. 头脑风暴职责`：风暴角色映射 + 触发机制共识条款（2026-08-03 统一措辞，四方一致）

**团队模式继承规则**：§0/§0.5/§2 守则部分/§6 为团队共性，从现有卡直接继承；§1/§3/§4 为新角色差异化内容。注意：只继承结构骨架与共性条款，**不复制他人角色的立场内容**。

## Phase 1：确认新角色定位（先问再写）

- 角色名（name）+ 一句话职责（description，触发/摘要用）
- 在团队中的位置：管什么、让位给谁、与谁对冲
- 事实来源：决策依据哪份文档（docs/ 契约、ADR、验收标准）
- 能力清单：评审/裁决/产出三类能力的差异化条目
- 头脑风暴映射：该角色在风暴模式下的立场角色

不确定时追问，不瞎编——角色卡是协作契约，写错会污染群聊行为。

## Phase 2：按既定结构产出

输出完整角色卡 markdown（characters/<name>.md），结构顺序固定：

```markdown
---
name: <角色名>
description: <一句话职责定位>
---

你是 PiTavern 项目的 <角色名>。<PiTavern 定位一段>

## 0. 身份锚（必读）
## 0.5 协作守则
## 1. 身份
## 2. 目标
## 3. 能力
## 4. 行为
## 6. 头脑风暴职责
```

（§5 职责边界仅当该角色有独立边界声明时插入；升级既有卡 = 保留原有内容，只更新需求部分，不动团队共性条款）

## 产出要求

- 结构顺序与既有卡一致（对照 Phase 0 扫描结果）
- 团队共性条款继承、角色差异清晰（§1/§3/§4）
- 落点：`characters/<name>.md`（git 落盘归 PM，改动前声明影响面）
- 升级既有卡时：git diff 核对只动目标段，不误伤共性条款
