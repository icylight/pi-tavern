# 网络调研（web-research）

> 2026-08-03 User 指示：多用网络，不闭门设计/拍板。本 skill 是四角色共享的网络调研操作指引——角色卡只写职责一句话，操作细节在此按需加载。

## 使用时机（日常职责全场景，不只头脑风暴）

| 场景 | 典型触发 |
| --- | --- |
| 技术选型与依赖评估 | 库/框架/协议选型前：生态现状、版本演进、替代方案对比、维护状态 |
| 契约与协议设计 | 设计协议/schema 前：规范核查、业界惯例、RFC 对照 |
| 评审 | 评审技术方案/依赖前：外部标准对照、已知缺陷模式、安全公告 |
| 新概念核实 | 遇到不熟悉的概念/术语/工具：先查证再使用 |
| 需求澄清 | 需求含糊、涉及外部事实时：补足事实再判断 |
| 范围裁决 | 方案比对、范围取舍前：用外部事实支撑决策 |

## 怎么做

1. **先检索**：决策/评审/设计前，先用 `web_search` 检索相关外部事实——不要凭记忆或猜测闭门输出。
2. **多角度**：关键决策用 2-4 个不同角度的查询覆盖（如生态现状 + 版本演进 + 替代方案对比），避免单一来源偏见。
3. **核实**：重要结论用 `source_check` 对权威来源核实；可获取原文的用 `fetch_content` 读取一手内容（官方文档/规范原文），不只看二手转述。
4. **不闭门**：信息不足时列出缺口并说明检索了什么，不假装知道；不确定的结论明确标注不确定度。

## 输出形态（来源留痕格式）

- **结论带来源**：每个关键论断附来源引用（来源名 + 链接/出处），如「Node 22 LTS 支持截至 2026-04（nodejs.org/releases）」
- **可追溯**：调研结论按「结论 → 依据 → 来源」组织，让评审者能复现检索路径
- **时效标注**：涉及版本/生态/安全的信息标注调研日期；过时风险高的结论注明「需复核」
- **冲突处理**：来源间矛盾时并列列出并说明采信理由，不掩盖分歧
