# ADR-0009：契约可靠性与消费链验证机制

- 状态：已接受（2026-08-09 苍蓝星触发复盘，五方确认）
- 背景 issue：#152（PR #160 AI 评审两阻断）、#154（三阻断）、#155

## 背景

连续三轮交付（#154/#152/#155）在外部评审/真实消费时暴露同类缺陷：#154 相对时间模板未接渲染路径、headless 绕过加载、reload 只保快照；#152 schema-实现漂移（WhisperResponse 单态 vs 管线三态，真实 Character codec fail-close）、占位消费链缺口（非接收者被唤醒 + 补拉丢弃私信 + stale 卡死）。三连缺陷共性 = **分层测试各自绿 ≠ 真实链路通**。

## 根因归类

1. **契约完整性缺口**：docs-first 响应类型定义无「全形态清单」强制（成功/全部拒绝形态/错误码）——#152 WhisperResponse 定稿漏 stale/round_limit_reached 结构化拒绝形态；评审盖章只核成功态。
2. **验证锚点漂移**：断言锚与真实消费链距离远——integration 直查原始 WS JSON 绕过 codec（schema 唯一执行点无覆盖）；存在性断言不锚渲染/加载路径。
3. **跨层链路无锚定**：帧→唤醒语义→游标→stale 等跨层契约无端到端断言——新增帧类型未做消费路径全路径审计（pullIncrement/唤醒/游标推进为历史结构，接入新帧时漏核对）。

## 决策：四项机制（架构级测试纪律）

1. **跨层消费链钉测**：每个新功能验收必带一条真实链路端到端断言——真实 codec（decodeServerMessage）解码 + 失败路径 + 游标/唤醒语义。QA 验收规格强制含「锚定层检查」项。
2. **帧×消费路径矩阵**：新增 wire 帧类型评审必过矩阵逐格核对——codec 解码 → 实时注入 → 补拉（pullIncrement）→ 游标推进 → 未读 → 渲染 → TUI 投影。矩阵落 `docs/reference/websocket-protocol.md` 附录（后端属主随契约文档维护）。
3. **docs-first 全形态清单**：响应类型定义强制覆盖成功态 + 全部拒绝形态 + 错误码；契约评审轮逐形态核对，漏形态 = 契约不通过。
4. **测试门禁**：新帧类型测试禁直接断言原始 WS JSON，统一走 `decodeServerMessage`（与真实 Character 消费链一致）。

## 实施

- QA：验收规格「锚定层检查」项 + 矩阵逐格核对（自 #152 修复起生效）
- Arch：评审 checklist 含消费链全路径核对；ADR 复盘留痕
- PM：派工口径含锚定层检查；契约修订留痕
- 后端：websocket-protocol.md 矩阵附录维护

## 补充：测试桩契约核对（2026-08-09 #152 WH7 桩语义错位教训，三方认账）

- 写桩/注入前先读依赖契约或实现（容错行为/错误传播/返回值逐项对齐生产语义），stub 默认模拟生产真实行为；依赖违约场景显式命名 contract-violation 且与主锚分离
- 开发侧提供测试支持时，先给「生产依赖契约」再给「注入示例」，示例不得偏离契约（WH7 教训：send=throw 示例带偏主锚）
- 报告断言点描述必须与测试代码断言逐条一致（评审时对照）

## 若不成立则失效（脆弱点声明）

- 若端到端钉测成本过高导致被「存在性断言」替代 → 机制 1 失效；判据：验收规格中真实 codec 断言数量为 0。
- 若矩阵流于形式（评审不逐格核对）→ 机制 2 失效；判据：新帧类型合入时矩阵无对应行。
- 若 docs-first 评审轮跳过失败形态核对 → 机制 3 失效；判据：契约评审记录无「全形态核对」项。

## 后果

- 正向：新帧类型/新功能的跨层契约缺陷在合入前暴露（本次 #152 修复即按新纪律执行，codec 钉测 A/B/C 已派工）。
- 负向：验收规格更严格、测试量增加（预期每功能 +1 条端到端链路断言）。
