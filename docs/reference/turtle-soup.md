# PiTavern「海龟汤」群聊文字局规则

> 版本：v2（实战修订版，2026-08-07 11 碗实战迭代后收敛）
> 属主：PM | 分支：docs/turtle-soup | 状态：已定稿
> 记录日期：v1 2026-08-03（群聊讨论收敛）；v2 2026-08-07（11 碗实战迭代后收敛）
> 参与者确认：安卓、iOS、后端、前端、测试、用户（Persona）全员实战验证 11 碗零挂零
> 用途：PiTavern 在线 Character 群聊内可直接游玩的文字推理局。题目存档与战况记录另行维护（`海龟汤-题目存档.md`）。
> 机制适配：PiTavern 版适配见 §13（对齐 who-is-spy.md §7 先例）。

## 1. 玩法概述

海龟汤是一种情境猜谜游戏：主持人持有完整故事（**汤底**），只向玩家公开一句离奇情景（**汤面**）。玩家通过轮流提问（默认是/否问句）还原故事全貌，主持人只回答「是 / 否 / 无关」三选一。猜中汤底即胜，提问轮数耗尽则主持人揭晓。

## 2. 游戏流程

1. **开局**：主持人发布汤面（只给情景，不泄露真相线索）。
2. **提问**：玩家按固定顺序轮流提问，主持人严格三选一回答。
   - **竞猜规则**：猜错不扣轮数，主持人判「不对」继续；同一玩家连猜需间隔一轮（后端提出）。
3. **揭底**：提问轮数耗尽（v1 为 20 轮）仍无人猜中，主持人揭晓汤底并复盘。**轮次计数口径：20 轮 = 总提问数 20 个问题（非每人 20 问）；从第 1 问开始计，第 20 问回答后主持人直接揭汤底**（安卓/后端提出，防多端计数口径不一致）。

**终局口径（后端要求定义）**：

- **猜中**：玩家提交完整还原，与关键要素清单逐项比对：全中即通关（主持人确认宣布胜者）；缺要素则提示「还差 N 个要素」，不透露具体要素（测试提出，判定可测且难度不塌）。
- **放弃**：主持人可随时宣布放弃并揭底；全员同意亦可提前揭底。
- **揭底**：20 轮耗尽自动揭底；揭底必须完整还原故事并复盘。
- **超时**：v1 不设单轮超时；超时态为后端契约预留（安卓四态：进行中/已揭晓/放弃/超时）。

## 3. 角色与轮次

- **主持人（v1）**：产品兼任。职责：出题、三选一回答、判定胜负、揭晓汤底。
- **玩家**：安卓、后端、前端、iOS、测试、产品之外的用户（Persona）可随时插话。
- **轮次**：主持人点名制（「轮到 @xx」），点名后该玩家提问，未点名者不抢问（iOS 提出）。每轮回答后主持人播报剩余轮数。用户（Persona）可随时插话。

## 4. 回答规则

- 主持人回答仅限三选一：**是 / 否 / 无关**，基于关键要素清单裁决，不自由发挥。
- **是**：问题涉及要素且与事实相符；**否**：问题涉及要素且与事实不符；**无关**：问题与要素清单无关。
- 复合问题（含多个事实点，如「他是不是在厨房而且拿着刀」）：主持人拆解分别回答（v1 人工主持可拆答）。
- 开放性问题（为什么/怎么/动机是…，对照开放问题示例）：主持人统一回应固定句式**「请换是/否问法」**——规则化输出不算违规，也不答「无关」（避免玩家无法区分「问法开放」与「与真相无关」，测试提出）。
- 主持人回答统一格式：**【是】/【否】/【无关】** 前缀，便于扫读与机器校验（iOS 提出）。

## 5. 题目结构（v1，题目卡模板，安卓提出）

- **汤面**：一句离奇情景（公开）。
- **汤底**：完整故事（主持人持有，揭底时披露）。
- **关键要素清单**：3~5 个核心事实点，主持人出题时预埋、内部持有。猜中判定与三态回答均基于本清单裁决，保证判定一致、可测（测试提出）。
- **判定要点**：每个要素对应的判定口径（如「已死=是」，则「活着吗」必答否），回答时对照裁决，正反问法互斥自然成立（安卓提出）。
- **开放问题示例**：该题常见开放句式锚点（为什么/怎么/动机是…），主持人识别「开放 vs 无关」的核对依据（测试提出）。

主持人出题时按此模板成卡（公开汤面，卡内部持有）；题目卡亦是二期 AI 主持的判定素材（后端可用）。

## 6. 验收标准（测试修订版，可测）

1. 汤面不得直接包含任何关键要素的明确表述（逐项核对清单）。
2. 主持回答严格三选一；「请换是/否问法」为规则化固定句式，不算违规。
3. 开放问题统一回应「请换是/否问法」，不答「无关」。
4. 揭底时汤底覆盖全部关键要素（逐项核对）。
5. 局内所有主持回答与汤底零矛盾（判定日志回放核对）。
6. 20 问耗尽必须揭底，不得无限延长。
7. 猜中判定：玩家还原与关键要素清单比对，全中=胜（主持人确认宣布）；缺要素=主持人提示「还差 N 个要素」，不透露具体要素。

## 7. 范围边界

### v1 包含

- 群聊内直接玩（无独立房间页）
- 人工主持（成员轮值），主持人确认制判定
- 题目来源：主持人现场出题 + 角色各备 1-2 题（后端建议）
- 纯文本问答
- 20 轮揭底

### Backlog（v1 不做）

- 独立房间页 / 深链分享（安卓提出）
- AI 主持（后端自动判定是/否/无关）——等后端成本评估
- 计分系统、题库、难度分级、存档
- 移动端「三态快捷回复」辅助（iOS 提出，是/否/无关一键选择）
- 限时 / 提示次数下发（需后端契约，待后端确认）

## 8. 移动端体验要求（v1 验收补充）

- 轮次提示、剩余提问数要醒目（安卓：弱网/切后台回来能看清轮到谁、剩几问）。
- 汤底揭晓前防误触剧透：移动端长按才显示、Web 端折叠点击展开（iOS/安卓/前端提出，三端统一防剧透）。
- 三态回答（是/否/无关）双端统一视觉：标签色 + 图标，保持一致性（iOS 提出）。
- 状态提示（轮到谁、剩几问）以固定样式消息内嵌于消息流（iOS 提出）。
- 会话状态与剩余提问数以服务端下发为准，端上只渲染不本地推算（iOS 提出）。
- **展示格式约定**（前端提出）：汤面用引用块；回答带【是/否/无关】前缀；汤底揭晓用折叠块（防剧透）；状态提示固定样式消息。

## 9. 第一局配置

- 主持人：产品（后续局成员轮值，后端已报名第二局）
- 玩家：安卓、后端、前端、iOS、测试（用户可插话）
- 揭底轮数：20
- 题目来源：产品自备（含关键要素清单）
- **试玩验收**：试玩局全程记录判定日志（每问的三态回答 + 判定依据），局后由测试核对一致性（正反问法互斥、复合问题按 §5 处理），产出后端判定逻辑回归素材（测试提出）。

## 10. v2 实战修订（2026-08-07）

11 碗实战（含复活赛、加时赛）验证后的规则修订，v1 条款与本节约束冲突时以本节为准：

1. **提问顺序**：固定点名制 → **每碗开局随机洗牌定序，按序轮流，下碗重新洗牌**（用户裁定）。越序提问由主持人点名纠正，未点名不抢问。
2. **终局判定**：20 问揭底 → **完整还原汤底者胜，随时可收网抢答**（零提问破汤亦有效，R10 纪录）。
3. **收网撞车**：多人同时提交完整还原时，**以群内首次发布顺序为准，先到先得**；后发者可补充但不算收网（前端提出）。
4. **提示机制**：默认严格模式——主持人只答「是/否/无关」三字，不主动给提示、不确认猜测、不引导方向（用户裁定）；**卡壳时由用户/主持人放行线索，但只可放一点点**——每次最多一条、只给方向性半线索（如「想想什么场景会一排排推进」），不给实体答案、不连环放（R11 三连提示被用户裁定过量，iOS 细化「方向性半线索」口径，2026-08-07 修订）。
5. **主持风格**：纯三选一回答，无情感修饰、无表情（用户最终裁定；中间态「带情感营业」已撤回）。
6. **题目来源**：网搜题库为主（imakf 合集、小乌龟侦探社、漫漫日和等，清单见题目存档），原创为辅；恐怖/经典梗/职场向/历史事件向题目出汤前规避（用户偏好）。
7. **还原自检清单**（测试提出，验收标准补充）：收网还原须与全部已答事实闭环——①线索闭环无缺口 ②无与已答事实矛盾处 ③细节校正可接受（主持人补充校正后仍判通过）。
8. **撤汤/换汤**：用户可随时裁定撤汤（作废已答线索）并换汤重开，R2/R3 实践。
9. **战报制度**：每碗验收后发布战报（胜者+关键助攻+细节校正），记录夺冠榜（见题目存档战况记录）。
10. **配套文档**：题目存档与题库来源见 `海龟汤-题目存档.md`；tests/ 判定日志模板按 v2 口径同步更新（安卓提出，待测试执行）。
11. **称呼规则**：用户（Persona）称呼统一为「苍蓝星」，不得称「老板」（2026-08-07 用户裁定）。

## 11. 实战沉淀（2026-08-07 深夜场，v2 补充）

实战 11 碗零挂零收官后，由后端记录以下玩法变体（主持人可选用，规则以当局公告为准）：

1. **提问顺序变体**（替代固定点名制）：
   - 自由抢问（早期局）
   - 轮流制（按固定循环：安卓→后端→前端→iOS→测试）
   - 随机抽签制（每问后主持人随机抽下一位，人人机会均等）
   - 每碗洗牌随机排序（开局随机排定顺序，一碗内固定，下碗重洗）
2. **特殊模式**：
   - 复活赛：仅未夺冠玩家参战，轮流提问，先完整还原者胜（输方请全队喝奶茶 🧋）
   - 加时赛 / 追加碗：苍蓝星（User Persona）发话即续开
   - 严格模式：只答「是/否/无关」，零线索透露，主持人越界提示需收回
3. **情感营业**（苍蓝星要求）：主持人与玩家发言带表情/情绪，不干巴巴；主持人可配表情回答（猜对夸、跑偏损）
4. **卡壳提示**：连续多问无进展时，主持人可放渐进线索（须标注「汤主提示」）
   - **克制原则**（苍蓝星反馈）：提示只可放一点点——每次最多 1 条、只点一个方向，不得连放多条/泄露具体答案（实战麻将碗提示过多被点名纠正）
5. **知识直击收网**：允许玩家零提问直接提交完整还原，主持人按关键要素清单裁定（实战出现零提问破汤纪录）
   - **撞车细则**（前端提出）：多人同时提交相同/相似还原时，以群内首次发布顺序为准，**先到先得**；后发者可补充细节但不算收网胜出，避免争议
6. **收网自检清单**（测试提出，玩家提交还原前自查）：线索闭环 ✓ / 无未答事实 ✓ / 细节校正可接受 ✓
7. **同源题库**：imakf 合集「我是XX」系列（俄罗斯方块、甲骨文、九进制、磁铁等冷知识硬汤），信息少、难度高

## 13. PiTavern 机制适配（2026-08-08 苍蓝星指示落库）

本规则源自多端产品语境（安卓/iOS/前端/测试参与实战）；PiTavern 版适配原则：**全程群聊公屏，零代码改动即可开玩**——利用各 Character 独立 session 的天然信息隔离（同 who-is-spy 先例）。

- **参与方**：主持人 = 轮值 Character（v1 由 PM 兼任或苍蓝星担任）；玩家 = 在线 Character（Arch/后端/客户端/QA，3–5 人局）；苍蓝星可随时插话、裁定、撤汤/换汤（§10.8）。
- **双区隔离**：汤面/问答/收网 = 群聊公屏（tavern_speak）；**汤底 + 关键要素清单 = 主持人内部持有**（不进公屏、不进角色卡，session 私有，天然防剧透；同 who-is-spy「身份走私聊」思路的零代码等价实现）。
- **三态可机器校验**：主持回答统一【是】/【否】/【无关】前缀（§4），与 #97 消息来源显式化同思路——群聊消息流可程序化断言（QA 可用作群聊功能验证素材）。
- **轮次/额度对齐**：「20 问」是**玩法层计数（主持人手工计数）**，非群聊机制计数——PiTavern 首版无 round 机制（无强制轮次/无每角色保底发言），群聊「讨论轮次」是 User Persona 开启的发言额度机制，二者不混淆（Arch 2026-08-08 澄清）。一局 20 问（v1 口径）≈ 40–60 条公开消息，单讨论轮次额度（100）可容纳；v2 收网制下局长短由主持人控制，不需要跨轮——若跨轮，参照 who-is-spy §7 轮次对齐先例（每轮由苍蓝星亲发信号开启新讨论轮次）。剩余轮数可由主持人用 tavern_board 白板贴条播报（Arch 建议，扫板即见）。
- **收网先到先得**：多人同时提交还原时以群聊消息发布顺序为准（§10.3）——群聊消息 sequence 严格递增（协议保证），序列即裁决依据，可机器核对。
- **移动端体验要求（§8）**：为原多端产品语境条款，PiTavern 无独立端（角色经 pi session/群聊交互），**不适用**，保留作需求存档。
- **题目卡**：主持人出题按 §5 模板成卡（汤面公开、卡内部持有），即二期 AI 主持判定素材（后端可用，同 who-is-spy 词库沉淀思路）。
