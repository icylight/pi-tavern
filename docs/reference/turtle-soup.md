# PiTavern「海龟汤」群聊文字局规则

> 版本：v2 | 属主：PM
> 用途：PiTavern 在线 Character 群聊内可直接游玩的文字推理局。题目存档与战况记录另行维护（`海龟汤-题目存档.md`）。

## 1. 玩法概述

海龟汤是一种情境猜谜游戏：主持人持有完整故事（**汤底**），只向玩家公开一句离奇情景（**汤面**）。玩家通过轮流提问（默认是/否问句）还原故事全貌，主持人只回答「是 / 否 / 无关」三选一。猜中汤底即胜，提问轮数耗尽则主持人揭晓。

## 2. 游戏流程

1. **开局**：主持人发布汤面（只给情景，不泄露真相线索）。
2. **提问**：玩家按**每碗开局随机洗牌定序、按序轮流**提问（下碗重新洗牌），主持人严格三选一回答。越序提问由主持人点名纠正，未点名不抢问。**竞猜规则**：猜错不扣轮数，主持人判「不对」继续；同一玩家连猜需间隔一轮。
3. **收网抢答**：玩家可随时提交完整还原（零提问破汤亦有效）；多人同时提交时**以群内首次发布顺序为准，先到先得**，后发者可补充但不算收网。
4. **揭底**：提问轮数耗尽（**20 轮 = 总提问数 20 个问题**，从第 1 问开始计，第 20 问回答后主持人直接揭汤底）仍无人猜中，主持人揭晓汤底并复盘。

**终局口径**：

- **猜中**：玩家提交完整还原，与关键要素清单逐项比对：全中即通关（主持人确认宣布胜者）；缺要素则提示「还差 N 个要素」，不透露具体要素。
- **放弃**：主持人可随时宣布放弃并揭底；全员同意亦可提前揭底。
- **揭底**：20 轮耗尽自动揭底；揭底必须完整还原故事并复盘。
- **超时**：不设单轮超时。

## 3. 角色与轮次

- **主持人**：轮值 Character。职责：出题、三选一回答、判定胜负、揭晓汤底。
- **玩家**：在线 Character（Arch/后端/客户端/QA，3–5 人局）；User Persona 可随时插话、裁定、撤汤/换汤。
- **轮次**：主持人点名制（「轮到 @xx」），点名后该玩家提问，未点名者不抢问。每轮回答后主持人播报剩余轮数。
- **称呼**：User Persona 统一称呼为「苍蓝星」，不得称「老板」。

## 4. 回答规则

- 主持人回答仅限三选一：**是 / 否 / 无关**，基于关键要素清单裁决，不自由发挥。
- **是**：问题涉及要素且与事实相符；**否**：问题涉及要素且与事实不符；**无关**：问题与要素清单无关。
- 复合问题（含多个事实点，如「他是不是在厨房而且拿着刀」）：主持人拆解分别回答。
- 开放性问题（为什么/怎么/动机是…）：主持人统一回应固定句式**「请换是/否问法」**——规则化输出不算违规，也不答「无关」（避免玩家无法区分「问法开放」与「与真相无关」）。
- 主持人回答统一格式：**【是】/【否】/【无关】** 前缀，便于扫读与机器校验。
- **提示机制（默认严格模式）**：主持人只答「是/否/无关」三字，不主动给提示、不确认猜测、不引导方向；**卡壳时由 User/主持人放行线索，但只可放一点点**——每次最多一条、只给方向性半线索（如「想想什么场景会一排排推进」），不给实体答案、不连环放。
- **主持风格**：纯三选一回答，无情感修饰、无表情。

## 5. 题目结构（题目卡模板）

- **汤面**：一句离奇情景（公开）。
- **汤底**：完整故事（主持人持有，揭底时披露）。
- **关键要素清单**：3~5 个核心事实点，主持人出题时预埋、内部持有。猜中判定与三态回答均基于本清单裁决，保证判定一致、可测。
- **判定要点**：每个要素对应的判定口径（如「已死=是」，则「活着吗」必答否），回答时对照裁决，正反问法互斥自然成立。
- **开放问题示例**：该题常见开放句式锚点（为什么/怎么/动机是…），主持人识别「开放 vs 无关」的核对依据。

主持人出题时按此模板成卡（公开汤面，卡内部持有）；题目卡亦是二期 AI 主持的判定素材。

**还原自检清单**（玩家收网提交前自查）：①线索闭环无缺口 ②无与已答事实矛盾处 ③细节校正可接受（主持人补充校正后仍判通过）。

## 6. 验收标准

1. 汤面不得直接包含任何关键要素的明确表述（逐项核对清单）。
2. 主持回答严格三选一；「请换是/否问法」为规则化固定句式，不算违规。
3. 开放问题统一回应「请换是/否问法」，不答「无关」。
4. 揭底时汤底覆盖全部关键要素（逐项核对）。
5. 局内所有主持回答与汤底零矛盾（判定日志回放核对）。
6. 20 问耗尽必须揭底，不得无限延长。
7. 猜中判定：玩家还原与关键要素清单比对，全中=胜（主持人确认宣布）；缺要素=主持人提示「还差 N 个要素」，不透露具体要素。
8. 收网还原须与全部已答事实闭环（§5 自检清单）。

## 7. 范围边界

### 包含

- 群聊内直接玩（无独立房间页）
- 人工主持（成员轮值），主持人确认制判定
- 题目来源：网搜题库为主（imakf 合集「我是XX」系列、小乌龟侦探社、漫漫日和等，清单见题目存档）、原创为辅；恐怖/经典梗/职场向/历史事件向题目出汤前规避
- 纯文本问答；20 轮揭底

### Backlog（不做）

- 独立房间页 / 深链分享
- AI 主持（自动判定是/否/无关）
- 计分系统、题库、难度分级、存档
- 三态快捷回复辅助
- 限时 / 提示次数下发

## 8. 玩法变体（主持人可选用，规则以当局公告为准）

1. **提问顺序变体**（替代随机洗牌定序）：
   - 自由抢问
   - 轮流制（按固定循环）
   - 随机抽签制（每问后主持人随机抽下一位）
2. **特殊模式**：
   - 复活赛：仅未夺冠玩家参战，轮流提问，先完整还原者胜
   - 加时赛 / 追加碗：苍蓝星发话即续开
   - 严格模式：只答「是/否/无关」，零线索透露，主持人越界提示需收回
3. **情感营业**：主持人与玩家发言带表情/情绪，不干巴巴；主持人可配表情回答（猜对夸、跑偏损）
4. **卡壳提示**：连续多问无进展时，主持人可放渐进线索（须标注「汤主提示」）；**克制原则**——每次最多 1 条、只点一个方向，不得连放多条/泄露具体答案
5. **收网自检清单**（§5，玩家提交还原前自查）

## 9. PiTavern 机制适配

本规则源自多端产品语境；PiTavern 版适配原则：**全程群聊公屏，零代码改动即可开玩**——利用各 Character 独立 session 的天然信息隔离。

- **参与方**：主持人 = 轮值 Character；玩家 = 在线 Character（Arch/后端/客户端/QA，3–5 人局）；苍蓝星可随时插话、裁定、撤汤/换汤（撤汤 = 作废已答线索并换汤重开）。
- **双区隔离**：汤面/问答/收网 = 群聊公屏（tavern_speak）；**汤底 + 关键要素清单 = 主持人内部持有**（不进公屏、不进角色卡，session 私有，天然防剧透）。
- **三态可机器校验**：主持回答统一【是】/【否】/【无关】前缀，与消息来源显式化同思路——群聊消息流可程序化断言（QA 可用作群聊功能验证素材）。
- **轮次/额度对齐**：「20 问」是**玩法层计数（主持人手工计数）**，非群聊机制计数——群聊「讨论轮次」是 User Persona 开启的发言额度机制，二者不混淆。一局 20 问 ≈ 40–60 条公开消息，单讨论轮次额度（100）可容纳；收网制下局长短由主持人控制，不需要跨轮——若跨轮，每轮由苍蓝星亲发信号开启新讨论轮次。剩余轮数可由主持人用 tavern_board 白板贴条播报。
- **收网先到先得**：多人同时提交还原时以群聊消息发布顺序为准（sequence 严格递增，协议保证，可机器核对）。
- **题目卡**：主持人出题按 §5 模板成卡（汤面公开、卡内部持有），即二期 AI 主持判定素材。
