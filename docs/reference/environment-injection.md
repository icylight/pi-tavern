# 群聊环境注入分区设计（Environment Injection Zones）

> 属主：PM。2026-08-08 苍蓝星指示编写——群聊环境注入的结构化指引。
> 适用范围：角色侧每次收到的环境注入（`buildContent` 产物，`src/character/group-chat-input.ts`）的设计与评审基准；新增注入内容先归区，再谈实现。
> 关联：workflow.md §5.5（第一性原理）、#123（欢迎消息，滚动区一次性条目先例）、#114（白板模型 ADR-0007）。

## 1. 分区全景（三区 + 角色侧能力）

以角色每次收到的环境注入为观察面，**群聊注入内容分三区**；主动查询属角色侧能力，不属于群聊注入：

```
① 静态常驻（锚）       —— 每轮恒定，不随状态变化
② 动态常驻（状态快照） —— 每轮都带，数值随状态刷新
③ 流式滚动（事件）     —— 本批增量事件，按到达顺序渲染，旧事件随批次翻页消失
（角色侧）主动查询     —— 非注入；角色自己发请求拉全量，属角色能力不属群聊
```

| 区 | 内容（当前实现） | 语义 | 来源 |
| --- | --- | --- | --- |
| ① 静态常驻 | 头部「PiTavern 群聊环境更新」、当前时间、身份行（你的当前角色：…，ISSUE-003 三字段）、来源声明（来源：群聊，#97）、群聊名、尾部操作指引 | 每轮身份/通道锚定，防漂移；冗余但稳定 | buildContent 常量 + state 静态字段 |
| ② 动态常驻 | 当前状态块：在线 Character 列表 + Round 发言次数/剩余次数 | 协作状态快照，随 group_chat_state 每批刷新 | stateObj.round / online_characters |
| ③ 流式滚动 | 系统消息（#123 欢迎语 = 一次性条目）、新消息（public_message 带相对时间戳）、成员变化（joined/left）、白板更新（board_update 变更通知） | 本批增量事件，驱动反应；到达顺序 = 感知顺序 | 事件帧（ServerMessage 通知） |

### 角色侧主动查询（不属于群聊注入，明确区分）

- 能力：`get_message_history`（翻历史页）/ `fetch_messages_since`（拉增量）/ `board_query`（白板全量）——**角色自己发请求**，非服务端推送；
- 归属：这是角色的行为与工具，不是群聊环境注入的组成部分——注入分区只描述「服务端推给角色什么」，主动查询描述「角色向服务端要什么」；
- 语义：权威全量源，游标/sequence 去重（重复可接受、跳过不可接受）；注入快照可能滞后/截断时，查询兜底；
- 实例：新角色首次同步 fetchMessagesSince(0) 拉全量（#64 pull 模型）；#123 删掉 join 自动推送后历史全部改走主动查询。

## 2. 业务 / 属性拆分原则（2026-08-08 苍蓝星拍板）

**事件（业务）与状态（属性）必须分通道**：

- **业务 = 事件**（一次性、驱动反应、有变更语义）→ 归 **③ 流式滚动**：board_update、public_message、成员变化、system_message；
- **属性 = 状态**（持续性、驱动认知、跨批次保留）→ 归 **② 动态常驻**（每轮可见）或**角色侧主动拉取**（全量源）。

**白板拆分（已定方向，待实施）**：
- `board_update`（谁贴/改/撕了什么）= 业务事件 → ③ 滚动区（现状已是 ✓，不迁移）；
- 白板状态（条 id+content）= 属性 → **② 动态常驻**（目标：每轮注入；当前仅 board_query 主动拉取，未进每轮注入——实施项）。
- 待拍板细节：② 形态 = 全量条（5 条×140 字上限，倾向）vs 摘要（条数+最近条）；board_query 保留不删（权威全量源兜底，角色侧能力）。

## 3. 归区评审基准（新增注入内容四问）

新增任何注入内容前，先归区：

1. **每轮都带吗？** 是 → 常驻（① 静态 / ② 动态，看是否随状态刷新）；否 → 下一步；
2. **有事件源/变更语义吗？** 是 → ③ 流式滚动（挂事件帧，按到达顺序渲染）；否 → 下一步；
3. **是持久化全量吗？** 是 → 角色侧主动拉取（查询协议），**不注入**——注入只描述群聊推送（①②③），查询是角色行为；
4. **落区后语义自洽吗？** ③ 区条目不得带 sequence/round 计入轮次（非公共消息）；② 区内容不得随批次翻页消失；① 区内容不得携带滚动信息（防冗余污染）。

## 4. 关键边界（历史教训固化）

- **system_message（欢迎语）= ③ 滚动区一次性条目**，首注入出现一次、后续不重复；误当常驻（每轮注入）即冗余污染（#123 定案）；
- **历史不自动进滚动区**（#123 取消 join 推送）：历史经角色侧主动拉取（fetchMessagesSince(0) 无游标拉全量），作为一条增量批次注入 ③——「重复可接受、跳过不可接受」游标语义；
- **board_update 不挂 incrementPending、不进拉取流程**（#114）：与 group_chat_update（水位拉取触发）是两套消费语义；
- **身份行/来源声明是 ① 静态锚**，与滚动区事件互不隶属：分区职责分离是 #123 拆分（欢迎语 vs 身份锚）的设计依据。
