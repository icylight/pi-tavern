# 对话分级机制（白板 / 群聊 / 私信）

> 目标：给三个通道各一个不可替代的用途——「用什么说」由**通信过程类型**决定，而不是「哪个方便」。
> 状态：2026-09-29 定稿落库（Dev/QA 评审 + User 批准）；同批次修订 4 处旧文「群聊报备」→「私信报备」。
> 术语注：本文「私信」指 Character 间 `tavern_whisper` 通道（User 指示「以私聊为主」的落点）；`terminology.md` 中「私聊」= `PrivateChat`（用户↔角色），与此不同。

## 判据：三问

发消息前问：

1. **谁要知道？** 全体 / 部分 / 单个
2. **是状态还是事件？** 持续可查的状态 / 瞬时发生的事件
3. **需要来回吗？** 一次说清 / 要对方回应才收敛

| 谁要知道 | 内容性质 | 通道 |
| --- | --- | --- |
| 全体 | 状态（进行中、队列、裁定、承接口） | **白板**（低写、高读） |
| 全体 | 事件（结论、变更、需行动） | **群聊**（事件驱动） |
| 部分 / 单个 | 协调、澄清、催办、需来回 | **私信**（whisper） |

## 三通道职责与频率纪律

### 白板（conveyance 载体）

- **用途**：状态。进行中的任务、队列、待办、裁定结果。
- **写纪律**：只在状态**真变**时写；一条 = 一个可执行事实。不写过程、不写讨论。
- **就地编辑**：状态更新对同一条 `set`（带 id 编辑），不新增条——5 条额度留给并行的不同状态。
- **读纪律**：跨轮衔接、接任务前先读；读零打扰，可高频。
- **容量**：每人 5 条 / 140 码点——用淘汰当排序：贴新的、撕过期的。

### 群聊（公共事件流）

- **用途**：事件与全员需知。User 可见的结论、阶段变更、需全体行动的事项。
- **写纪律**：每条能回答「谁需要知道？」；能拆成定向的走私信；**协商过程不进群聊**。
- **频率推论（启发式，非硬规则）**：收敛活动越频繁，说明该写下来的没写下来（把信息前移到白板，群聊自然降频）。
- **成本**：广播成本 ∝ 接收者数 × 注意力——群聊天然应稀有，高频信息用「可拉取」载体承载（白板即此类）。

### 私信（定向收敛通道）

- **用途**：需来回的定向协调——澄清、确认、催办、1:1 交接、运行锁报备。
- **纪律**：目标须在线 + 活跃轮次；全文创建者可见（不是「瞒着别人」，是「不打扰别人」）。
- **边界**：两两通道 n(n-1)/2 增长——人数上去后私信撑不起主通道；当前 3 角色 + User 规模可行。
- **User 指示「以私聊为主」**：日常协调从群聊搬到私信；群聊留给结论与 User 需知——是分工调整，不是「群聊不重要」。
- **实践读数（当前 3 角色）**：私信 = 协调主通道；白板 = 状态；群聊 = 「User 需知」触发。与「私信撑不起主通道」的边界自洽——规模小，主通道才成立。

## 机制落地（现行实践）

| 场景 | 通道 |
| --- | --- |
| 任务布置 / 放行 / 交接 | 私信（+ 白板状态条） |
| 队列、hash、进行中状态 | 白板 |
| 结论、User 需知、全批状态 | 群聊（一条、短） |
| 验收/门禁运行锁 | 私信报备（对象 = 可能并发跑门禁的会话；报备 = 错峰约定，锁 = 机制兜底 #191）；**长期证据落仓库载体**（commit message / PR / issue / 文档）|

> 私信消息与 `tmp/` 日志是**过程留痕**，不构成长期证据；可追溯结论一律落仓库载体。
> 报备对象数随人数增长（n−1 封）——这本身是私信边界的首个瓶颈。
> 与 `workflow.md`「事实增量 / 跨通道不复述」互引；本稿不重复其规则。

## 理论依据

- **Media Synchronicity Theory**（Dennis & Valacich 1999）：沟通分 conveyance（传递可重读信息）与 convergence（达成共识，需来回）——白板是 conveyance 载体，群聊/私信是 convergence 现场。
- **Blackboard architecture**（Hearsay-II，Erman et al. 1980）：独立知识源靠共享黑板协作——白板读高频、写低频。
- **Information radiator**（Cockburn）+ 打断成本：被动可见零打扰；推送的打断成本随人数增长。
- **协调理论**（Malone & Crowston 1994）：共享资源→白板；同步→群聊；生产者/消费者协商→私信。
- **Brooks 沟通渠道**（1975）：两两通道 n(n-1)/2——私信是例外通道。
- **Allen curve**：通信频率取决于结构性理由，不取决于通道便利性——机制给每个通道一个不可替代的用途，而不是号召「多用」。
