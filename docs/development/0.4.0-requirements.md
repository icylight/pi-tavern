## 2. Character 间私信

- 新增 LLM 工具 `tavern_whisper`，参数为 `{ character_id, content }`；仅支持 Character 向当前在线的其他 Character 发送，不支持 User Persona、自发自收、离线排队或已读状态。
- 私信要求存在活跃讨论轮次，与公开消息共用连续 sequence、轮次额度、消息大小限制、持久化失败恢复、未读优先、陈旧性检查和举手逻辑；失败发送不占额度。
- 使用独立持久化类型 `pi-tavern.whisper-message`，与 `pi-tavern.public-message` 写入同一群聊 JSONL，并在读取时合并为同一时间序消息流。0.3.x 历史无需迁移。
- 发送者、接收者和创建者看到 `A 向 B 悄悄说：<正文>`；其他 Character 只看到 `A 向 B 悄悄说了一句话`。历史查询也按当前 `character_id` 执行相同投影。
- 接收者走现有实时投递及忙态安全边界；其他 Character 不被主动唤醒，但占位事件仍属于其未读序列，后续发言前必须消费。
- 发送成功以目标在线校验通过、事件持久化、sequence/额度提交及通知发出为准；校验后掉线不回滚。发送者只获得工具结果，不额外注入自身事件。
- 原始 JSONL 明文保存私信；这是交互层隐私，不提供文件系统安全保证。
- 不增加运行时协议版本字段或兼容性校验；代码注释说明本地同版本实例假设，不支持混合版本互连。

## 3. 可配置群聊文案

> **2026-08-10 修订（#172）**：`/tavern-template-edit` 命令改为扩展自带 skill（包内 `skills/tavern-template-edit/SKILL.md` 随包分发）；**tavern_template_defaults 工具保留**（template skill 单源引用其返回的默认值/合法 key/占位符规则，不内嵌知识防双源漂移）。验收条目见 acceptance.md #172 SK1-SK8。

- `tavern.json` 新增可选 `message_templates`，指向相对该配置文件的独立 JSON 文案文件。
- 按 key 合并，优先级为项目配置 > 全局配置 > 内置中文；允许部分覆盖。缺失、无法解析或单项无效时 warning，并逐项回退，不阻止群聊启动。
- 第一版只覆盖公开消息、完整私信、私信占位、`秒前`、`分钟前` 五类渲染；实时注入、`tavern_history` 和创建者 TUI 共用同一模板集。欢迎语及命令、错误、工具、状态等文案不在本期范围。
- 模板只支持简单 `{placeholder}`。公开消息必须保留发送者与正文；完整私信必须保留发送者、接收者与正文；私信占位必须保留发送者、接收者且禁止正文；相对时间必须保留数量。未知、缺失或禁止的占位符均判为无效。
- 模板加载沿用配置生命周期：creator 在 `/tavern-new`、`/tavern-resume`、`/reload` 加载，Character 在 claim/join/reload 加载；不做文件监听或自动热更新。
- ~~新增 prompt command `/tavern-template-edit`，可携带自然语言参数~~（#172 起改为 skill，语义保留：默认建议编辑全局配置，但必须让用户选择全局、当前项目或其他配置；写入前展示 diff 并取得明确确认，写入后告知 reload/rejoin/resume 后才生效）。
- 新增仅供 LLM 调用的只读工具 `tavern_template_defaults`：无参数，返回完整中文默认值、合法 key、占位符规则和 JSON 骨架。idle 与 Character 状态可用，creator 与 joining 状态拒绝；不注册用户 slash command。（保留，#172 起作为 template skill 的单源引用）

## 4. `/tavern-resume` 展示完整历史

- 保留现有群聊选择、删除、`controller.startResume()`、SessionStore 和创建者服务恢复流程。
- 仅调整恢复完成后的 TUI 投影：移除 `JOIN_HISTORY_LIMIT = 10` 限制，展示该群聊完整历史，并保留现有 sequence 锚点避免同一当前 Session 重复投影。
- 创建者对历史私信始终看到完整正文；公开消息和私信使用文案配置中的统一渲染。
- 不调用 pi 的 `ctx.switchSession()`，不改变 `/tavern-new`，不新增空群聊持久化或 Session 切换机制。
